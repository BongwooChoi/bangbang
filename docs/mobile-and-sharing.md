# 모바일 PWA와 공유 설계

기준일: 2026년 11월 8일. 이 문서는 구현 요구사항이며, 현재 기능 구현이나 실제 기기 검증이 완료되었다는 뜻은 아니다.

## 모바일에서 우선할 경험

사용자는 링크를 열고 바로 음식점을 탐색할 수 있어야 한다. 로그인이나 PWA 설치를 검색·상세 보기·공유의 선행 조건으로 두지 않는다. 기본 지도 중심은 뱅뱅사거리이며 후보 범위는 [제품 기획](product-brief.md)을 따른다.

- 지도와 목록을 오가며 선택한 음식점을 유지한다.
- 하단 카드에서 음식점 이름, 추천 근거, 공유, 잇플 상세 보기 버튼에 접근할 수 있게 한다.
- 터치 버튼은 프로젝트 기준 최소 44×44 CSS px로 설계한다. iPhone 안전 영역, 화면 회전, 가상 키보드가 주요 조작을 가리지 않게 한다.
- 위치 권한은 사용자가 내 위치 기능을 눌렀을 때 요청한다. 거부해도 기본 지역 탐색을 사용할 수 있어야 한다.
- 지도 로딩 실패 시 목록과 안내를 제공한다. 로딩·빈 결과·오류를 구분하고 재시도 경로를 둔다.
- 키보드·스크린리더로도 음식점과 주요 버튼에 접근할 수 있게 한다.

- 점심 메뉴 결정을 돕는 ‘오늘의 한 집 뽑기’를 검색창과 분리된 강조 영역에 표시한다. 모바일에서는 전체 너비 버튼을 사용하며, 적용된 검색·필터 후보에서 무작위로 한 곳을 선택한다. 로딩·후보 없음은 이유를 표시한다.
- 자연어 조건은 별도 ‘AI 검색’ 버튼 또는 Enter로 제출한다. GPT-6 Luna가 가게명·업종·지역·단골·회식·고객층·정렬을 추출하고 API 조회 및 화면 필터에 적용한다. 해석한 조건과 미확인 조건을 보여준다. 검색어 지우기·필터 초기화·담은 맛집 전환 시 진행 중 요청을 취소하고 기본 탐색으로 복귀한다. 재검색은 이전 조건을 대체하며 수동 필터로 더 좁힐 수 있다.

## PWA 범위

HTTPS, Web App Manifest, 앱 이름, 192px·512px 아이콘, 시작 URL, standalone 표시 모드를 준비한다. 브라우저와 운영체제마다 설치 지원·방법이 다르므로 기능을 감지하여 안내한다. iOS에 공통 설치 팝업이 자동으로 뜬다고 가정하지 않는다. [MDN 설치 안내](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)

서비스 워커는 앱 화면을 구성하는 정적 파일과 오프라인 안내를 대상으로 설계한다. 잇플 응답, 식당 원본 데이터, 지도 타일을 일괄 캐시하지 않는다. 식당 정보의 캐시는 제공자의 허용 범위가 확인된 뒤 정한다. 오프라인에서 최신 영업 상태나 새로운 추천을 제공하는 것처럼 표시하지 않는다. 업데이트 시 구버전 캐시를 정리하고 사용 중 화면이 갑자기 초기화되지 않도록 한다.

## 공유 흐름

1. 사용자가 음식점 한 곳 또는 후보 목록에서 공유를 누른다.
2. 카카오톡, 기기 기본 공유, 링크 복사 중 원하는 방법을 고른다.
3. 받는 사람은 우리 서비스의 고유 URL에서 해당 후보를 확인한다. 설치나 로그인을 요구하지 않는다.
4. 식당 이름·주소·추천 이유 바로 아래의 ‘이 집 더 알아보기’를 누르면 잇플 매장 상세 페이지를 현재 탭에서 연다. 버튼 아래에 이동 목적지를 안내하며 API의 `merUrl`을 변형 없이 연결한다. 매출·혼잡·고객층 정보와 공유 기능도 상세 화면에서 계속 제공한다.

공유 URL은 실제 추천 내용을 보여주는 페이지다. 잇플로 자동 이동하는 리다이렉트나 단축 URL로 만들지 않는다. 잇플 링크에 추적 파라미터를 붙이지 않는다. 우리 페이지를 거쳤더라도 인앱 브라우저 등으로 유입 출처가 사라질 수 있으므로 집계는 실제 기기에서 별도로 확인한다. [공모전 연결 안내](https://edu.bccard.ai/static/contest/apply.html)

2026년 11월 11일: 목록과 상세의 외부 링크는 `EatplLink`를 공유한다. 일반 클릭은 현재 탭에서 원본 주소를 열어 인앱 브라우저의 추가 창 전환을 줄이며, Ctrl/Cmd/중간 클릭의 브라우저 기본 동작은 유지한다. `noopener`와 `strict-origin-when-cross-origin`으로 출처를 보존한다. 알려진 인앱 브라우저에서는 Safari·Chrome으로 현재 페이지를 여는 안내와 주소 복사를 제공한다. 자동 외부 앱 실행이나 잇플 자동 이동은 하지 않는다. 공유 및 안내의 복사 주소는 `SITE_URL`의 운영 호스트를 사용해 배포 별칭이 확산되지 않도록 한다.

실제 링크 클릭에서만 `/api/outbound`로 비차단 진단 요청을 보낸다. `sendBeacon`이 큐에 넣지 못하면 `fetch(keepalive)`로 대체하며, 어느 쪽이 실패해도 원래 링크 이동을 막거나 지연하지 않는다. 서버는 시각, 목록/상세, 홈/공유, 일반/인앱/standalone, 현재/새 탭만 기록하며 IP·사용자 식별자·식당 데이터·검색문·전체 URL은 진단 메시지에 넣지 않는다. 이 기록은 **클릭 시도**이며 잇플 도착·체류·BC 인정 순사용자가 아니다. 우클릭 메뉴로 새 탭을 여는 등 페이지 클릭 이벤트를 거치지 않는 동작과 통신 실패는 누락될 수 있다.

기록 위치는 Vercel 프로젝트의 Logs에서 `/api/outbound` 또는 `eatpl_open` 검색이다. Hobby의 런타임 로그는 **1시간 보관**이므로 일별·누적 통계로 사용하면 안 된다. 장기 통계에는 별도 저장소 또는 본인 소유 분석 속성이 필요하다. Vercel 유료 플랜이나 BC의 GA4 속성을 추가하지 않는다. [런타임 로그 보관](https://vercel.com/docs/logs/runtime), [사용자 지정 이벤트 지원 플랜](https://vercel.com/docs/analytics/custom-events)

## 공유 방식과 대체 동작

| 방식 | 요구사항 |
| --- | --- |
| 카카오톡 | Kakao JavaScript SDK의 공유 기능 사용. 개발자 앱, JavaScript 키, SDK 도메인 및 제품 링크 도메인 등록 필요. 설정 실패 시 다른 공유 방법 유지 |
| 기기 기본 공유 | 사용자의 버튼 클릭에서 `navigator.share()` 호출. 기능 지원 여부 확인. 공유 대상 앱은 기기 환경에 따라 달라짐 |
| 링크 복사 | 기본 공유를 지원하지 않아도 사용 가능. 복사 성공 안내, 실패 시 선택 가능한 URL 제공 |
| 링크 미리보기 | 우리 페이지의 제목·설명·대표 이미지를 Open Graph 메타데이터로 제공. 실제 내용과 일치하고 사용 권한이 있는 이미지 사용 |

홈 링크는 ‘뱅뱅밥 · 말로 찾는 우리 동네 맛집’과 자연어 AI 검색 설명을 사용한다. 음식점 공유 페이지는 식당명·함께 식사하자는 설명을 유지한다. 공통 썸네일은 `/og-ai-search.png`(1200×630)이며 `node scripts/generate-assets.mjs`로 재생성한다. 이전 `/og-image.png`는 기존 링크 호환을 위해 남긴다. 운영 배포 후 [카카오 URL 메타 정보 관리](https://developers.kakao.com/tool/debugger/sharing)에서 홈 URL의 캐시를 초기화하고 새 미리보기를 확인한다.

카카오톡 공유에는 [Kakao.Share](https://developers.kakao.com/docs/latest/ko/kakaotalk-share/js-link)를 사용한다. 자동으로 지인에게 메시지를 발송하는 기능은 만들지 않는다. 사용자가 수신자를 선택하고 전송한다. SDK를 열었다는 사실만으로 전달 성공으로 기록하지 않는다.

Web Share API는 HTTPS 및 사용자 동작이 필요하고 브라우저 지원이 제한적이다. 취소는 오류 경고로 취급하지 않는다. 특정 SNS가 반드시 공유 목록에 표시되거나 링크를 특정 형태로 받아 준다고 보장하지 않는다. [MDN Web Share](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)

공유 URL에서 복원할 데이터는 조회 가능한 최소 식별 정보로 설계한다. API 키·개인정보·원본 데이터 전체를 URL에 넣지 않는다. 서버에서 공유 페이지를 만들기 위해 필요한 식별 정보 저장 방식은 잇플 이용 조건과 함께 검토한다. 삭제되었거나 조회할 수 없는 후보는 이유와 지도 복귀 버튼을 표시한다.

## 공개 개발과 배포

소스코드와 문서는 MIT 라이선스로 공개한다. 잇플 데이터·지도·사진은 해당 제공자의 조건을 따른다. 서비스 자격 증명은 로컬 환경 변수 및 호스팅의 환경 변수 설정으로 관리하고 저장소에 커밋하지 않는다. 공개 사용을 전제로 한 SDK 키라도 허용 도메인과 사용 범위를 설정한다.

사용자에게 직접 과금하지 않는 개인 프로젝트로 시작하며, Vercel 무료 운영을 우선한다. 다만 공식 정책은 개인·비상업 이용만 허용하며 금전적 이득을 목적으로 한 배포를 상업적 이용으로 정의한다. 공모전 리워드와 상금에 대한 적용은 불명확하므로 무료 이용 가능 여부를 확인 사항으로 남긴다. 배포 시 최신 조건을 재확인하며 유료 플랜으로 자동 전환하지 않는다. [Hobby 안내](https://vercel.com/docs/plans/hobby), [상업적 이용 기준](https://vercel.com/docs/limits/fair-use-guidelines#commercial-usage)

GitHub에서는 누구나 PR로 기여할 수 있도록 한다. Vercel 계정에 모든 기여자를 초대하는 것은 전제하지 않는다. 외부 PR의 Preview Deployment 권한과 환경 변수 노출 범위는 연동 시 확인한다. 실제 운영 도메인은 공모전과 Kakao 개발자 설정에 동일하게 등록한다.

## 구현 후 확인할 항목

- [ ] Android Chrome·Samsung Internet, iPhone Safari에서 지도·목록·필터·상세 동작
- [ ] 설치 전 브라우저와 홈 화면 설치 후 standalone 모드의 동작
- [ ] 좁은 화면·큰 글씨·키보드·스크린리더·안전 영역에서 핵심 버튼 접근
- [ ] 카카오톡 인앱 브라우저에서 공유 링크 열기와 외부 브라우저 전환 경로
- [ ] 카카오톡 앱 유무, SDK 실패, 기본 공유 미지원, 취소, 링크 복사 실패
- [ ] 음식점 및 후보 목록 URL의 직접 접근·새로고침·재공유
- [ ] SNS 링크 미리보기의 제목·설명·이미지와 실제 후보의 일치
- [ ] 오프라인 안내, 온라인 복귀, 서비스 워커 업데이트
- [ ] 최신 영업 상태를 과거 데이터로 단정하지 않는지 확인
- [ ] 등록 도메인에서 잇플로 실제 이동 후 대시보드 유효 사용자 반영 확인

실기기에서 실행하지 않은 항목은 통과로 기록하지 않는다. 구현 후 로컬 브라우저에서 확인한 내용과 실제 기기에서 남은 항목은 [검증 기록](verification.md)에 구분해 기록한다.
