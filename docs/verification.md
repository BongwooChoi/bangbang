# 첫 버전 검증 기록

## 검색과 랜덤 추천 구분 (2026년 11월 8일)

- 검색창 옆의 작은 셔플 버튼을 별도 추천 영역의 ‘오늘의 한 집 뽑기’로 옮겼다. ‘검색’ 버튼·Enter로 검색어를 적용하며 모바일에서 결과 목록을 연다. 랜덤 후보는 적용된 검색·필터를 따른다.
- 변경 전 테스트 22개와 변경 후 타입 검사·프로덕션 빌드·로컬 SEO 검사 통과. 합성 음식점 2곳으로 브라우저에서 로딩 중 비활성·문구, 검색 버튼·Enter, 카페 검색 후 해당 후보 뽑기, 검색 결과 없음·비활성, 검색어 지우기 복원을 확인했다. 실제 잇플 방문은 하지 않았다.
- Chromium 360px·1440px에서 가로 넘침 없음과 강조 버튼 배치를 확인했다. 실제 모바일 기기 검증과는 구분한다. 서비스 워커 셸 버전은 v5로 갱신했다.

## SEO·GEO 설정 (2026년 11월 8일)

- 기존 테스트 22개, 타입 검사, 최종 프로덕션 빌드 통과. `npm run verify:seo`로 홈·안내·robots·사이트맵·llms.txt·공유·오프라인 응답과 OG 이미지를 확인했다. 이 검사를 GitHub Actions에도 추가했다.
- 원본 HTML에서 지역 안내와 링크, 한국어 제목·본문, canonical, JSON-LD를 읽을 수 있으며 FAQ의 질문·답변이 실제 표시 본문과 일치함을 확인했다. 미리보기의 robots 차단·빈 사이트맵·noindex 헤더 설정과 대표 URL 검증, JSON-LD의 HTML 이스케이프를 별도로 확인했다.
- Chromium 360px에서 홈 안내와 안내 페이지를 확인했고 가로 넘침이 없었다. 음식점 목록과 잇플 링크는 기존 동작을 유지한다. 이는 실기기 검증과 별개다.
- Google·Bing·네이버에서 발급한 공개 소유권 확인 파일을 추가했다. 검색 서비스 등록·사이트맵 제출과 실제 색인 여부는 서로 구분한다.
- 운영 주소의 SEO HTTP 검사와 GitHub Actions가 통과했다. Google 소유권 확인 완료 및 사이트맵 상태 `성공`, 발견된 페이지 `2`를 확인했다. Bing XML 파일은 공개 GET에서 200/application/xml이지만 Bing 인증 서버가 접근 실패를 반환하여 메타태그 인증 경로를 추가했다.
- Bing은 직접 메타태그 검증에서도 실패했으나 Google Search Console 가져오기로 뱅뱅밥 1개 속성 등록에 성공했다. 사이트맵의 `Imported / Processing` 상태를 확인했다. Google 홈 URL 수동 색인 요청은 일일 할당량 초과로 접수되지 않았으며, 현재 색인 상태는 `발견됨 - 현재 색인이 생성되지 않음`이었다. 사이트맵 성공과 검색 노출 완료를 혼동하지 않는다.

- 네이버 소유권 확인용 HTML 파일을 배포하고 HTTP 200 및 발급 내용 일치를 확인했다. 해당 배포의 GitHub Actions [42445657294](https://github.com/BongwooChoi/bangbang/actions/runs/42445657294)와 운영 주소의 `npm run verify:seo`가 통과했다. 사용자 로그인·보안문자 입력 후 사이트 등록과 소유권 확인을 완료했다.
- 네이버 서치어드바이저에서 사이트맵 `https://bangbang-five.vercel.app/sitemap.xml`의 등록 시각 `26.11.08 13:17:26`을 확인했다. 웹 페이지 수집 요청 내역에 홈 `/` (`13:20:29`)과 안내 `/guide` (`13:21:00`) 두 건이 표시됐다. 요청 접수 증거이며 실제 수집·색인 완료를 의미하지 않는다.

## 전체 카테고리 누락 보완 (2026년 11월 8일)

- 변경 전 테스트 18개 통과. 기존 5개 도로 조회와 동일 주소의 중식·카페 조회를 비교해 매출 상위 100건 제한으로 인한 누락을 확인했다. 종전 146곳에서 보완 조회 시 220곳, 중식 6→23곳, 카페·간식 33→90곳이었다.
- 중식·카페 보완에서 공식 대분류 9종 전체와 카페로 확대했다. 한도에 도달한 도로만 추가 조회하는지, 모든 화면 카테고리의 후보가 병합되는지, 중복과 범위 밖 매장이 제거되는지, 추가 조회 실패 시 기존 후보와 부분 실패 상태가 유지되는지 테스트를 추가했다. 동시 호출 상한 및 429 이후 대기 호출 중단도 확인했다. 총 22개 테스트와 타입 검사 통과.
- 실제 확대 조회 중 제공자의 429 제한을 확인했으며, 이때 확보된 후보는 표시하고 일부 조회 실패를 안내한다. 추가 조회도 100건 제한이 있어 완전한 지역 전수 목록을 보장하지 않는다.
- 검색 옆 무작위 선택 버튼에 모바일에서도 보이는 ‘한 곳 뽑기’ 문구를 추가했다.
- 최종 실제 조회에서 `partial: false`, 총 336곳(한식 71, 면·분식 16, 고기 39, 일식 31, 중식 24, 양식·기타 58, 카페·간식 97)을 확인했다. 해당 시점의 추천 후보 수이며 지역 전체 매장 수가 아니다. 로컬 직접 조회는 약 2.7초였다.
- 최종 프로덕션 빌드 통과. Chromium 360px에서 버튼 문구 표시와 가로 넘침 없음, 카페 필터 97곳, 해당 조건의 무작위 후보 선택, 공유 URL 직접 접근 후 같은 후보 1곳 복원을 확인했다. 잇플 링크의 `noopener`와 `strict-origin-when-cross-origin` 속성을 확인했으며 실제 잇플 자동 방문은 수행하지 않았다.

## 추천·고객층 필터 확장 검증 (2026년 11월 8일)

- 기존 테스트 10개 통과를 기준으로 구현을 시작했다. 고객층 정규화, 성별·연령대의 동일 항목 매칭, 회식과 다른 필터의 교집합, 추천 점수와 결측값, 시간 구간 검증을 추가해 총 18개 테스트 통과. 타입 검사와 프로덕션 빌드 통과.
- Chromium 360px에서 ‘30대 여성 + 회식 후보’ 결과가 실제 API의 동일 조건과 일치하는지 확인. 카드의 일치 이유와 회식 배지, 상세의 고객층 순위·요일·시간 구간을 확인했다.
- 추천순·거리순 전환, 검색 결과 없음과 전체 조건 복원, 목록에서 지역 전환과 상세 열기, 지도 추천 후보 열기, 공유 링크 직접 접근을 확인했다.
- 목록 모드의 숨겨진 지도에서 Leaflet 이동 애니메이션이 0 크기를 계산해 발생하던 `Invalid LatLng object: (NaN, NaN)` 오류를 재현하고 수정했다. 수정 후 같은 모바일 동선에서 상세 표시와 오류 없는 실행을 확인했다.
- 360px·1440px 화면에서 가로 넘침 없음. 서비스 워커 업데이트 버튼으로 `bangbang-shell-v1`에서 `v2`로 전환하고 구 캐시 정리를 확인했다.
- 위 검증은 화면 크기 에뮬레이션이며 실제 휴대폰·카카오톡 전송 검증은 아니다.

검증일: 2026년 11월 8일. Windows의 Chromium 브라우저와 로컬 프로덕션 빌드를 사용했다. 모바일 검증은 화면 크기 에뮬레이션이며 실제 휴대폰 검증과 구분한다.

- 로컬 원본 서버를 중지한 뒤 새 URL 탐색에서 오프라인 안내 표시 확인. 서버 재시작 후 음식점 목록 복구 확인.
- 모바일 주요 버튼과 지도 마커에 접근 가능한 이름이 있는지 확인.
